247: ## 7. 핵심 도메인 시스템
248: 
249: ### 7-1. 온톨로지 캔버스 엔진 (M-V-C 아키텍처)
250: 
251: ```mermaid
252: graph LR
253:     subgraph Controller["OntologyCanvasEngine.ts"]
254:         State["상태 (노드, 카메라, 선택)"]
255:         Events["마우스/터치 이벤트 핸들러"]
256:         Tick["tick() → isDirty 플래그"]
257:     end
258: 
259:     subgraph Model["모델 계층"]
260:         Layout["OntologyLayout.ts\n(방사형 좌표, 궤도 수학)"]
261:         Network["OntologyNetwork.ts\n(BFS, 트리 탐색, 가중치)"]
262:     end
263: 
264:     subgraph View["뷰 계층"]
265:         Renderer["OntologyRenderer.ts\n(Canvas 2D 렌더링 파이프라인)"]
266:     end
267: 
268:     Events --> State
269:     State --> Tick
270:     Tick -->|isDirty=true| Renderer
271:     State --> Layout
272:     State --> Network
273:     Layout --> Renderer
274:     Network --> Renderer
275: ```
276: 
277: - **Phase 1 (모듈화):** 약 1,300줄의 단일체 엔진을 컨트롤러 + 레이아웃 + 네트워크 + 렌더러로 완전 분해.
278: - **Phase 2 (Dirty Flag):** `needsRedraw` 플래그로 실제 사용자 상호작용 및 물리 모션 계산 시에만 Canvas 렌더링 수행. 유휴 CPU → 0%.
279: - **Phase 3 (상태 동기화):** `useState`를 `useSyncExternalStore`로 교체하여 Yjs 데이터 구독 개편. 16ms 디바운스로 고빈도 Yjs 트랜잭션을 일괄 처리하여 노드 집중 조작 시 React UI 정지 현상 영구 해소.
280: - **Phase 4 (LOD 텍스트 컬링 및 1차 인접 렌더링):** 줌 비율에 따른 드로잉 분기와 더불어 활성 노드(`activeNodeId`)의 1차 인접 노드(직속 부모/자식)만 라벨 텍스트를 그리고 나머지는 벡터 원(Dot) 형태로 대체하는 LOD 기법 도입.
281: - **Phase 5 (Zero-Allocation 및 정수 인코딩):** 간선 드로잉 배치 맵의 키를 문자열 대신 비트 연산 기반 32비트 정수형(`(colorId << 17) | ...`)으로 변환해 문자열 생성 가비를 억제하고, Object Pool 패턴을 이식해 매 프레임 GC 발생을 원천 차단.

(M-V-C 아키텍처)\n\n```mermaid\ngraph LR\n    subgraph Controller["OntologyCanvasEngine.ts"]\n        State["상태 (노드, 카메라, 선택)"]\n        Events["마우스/터치 이벤트 핸들러"]\n        Tick["tick() → isDirty 플래그"]\n Canvas 렌더링 수행. 유휴 CPU → 0%.\n- **Phase 3 (상태 동기화):** `useState`를 `useSyncExternalStore`로 교체하여 Yjs 데이터 구독 개편. 16ms 디바운스로 고빈도 Yjs 트랜잭션을 일괄 처리하여 노드 집중 조작 시 React UI 정지 현상 영구 해소.\n- **Phase 4 (LOD 텍스트 컬링 및 1차 인접 렌더링):** 줌 비율에 따른 드로잉 분기와 더불어 활성 노드(`activeNodeId`)의 1차 인접 노드(직속 부모/자식)만 라벨 텍스트를 그리고 나머지는 벡터 원(Dot) 형태로 대체하는 LOD 기법 도입.\n- **Phase 5 (Zero-Allocation 및 정수 인코딩):** 간선 드로잉 배치 맵의 키를 문자열 대신 비트 연산 기반 32비트 정수형(`(colorId << 17) | ...`)으로 변환해 문자열 생성 가비를 억제하고, Object Pool 패턴을 이식해 매 프레임 GC 발생을 원천 차단.\n\n### 7-2. 실시간 협업 스택\n\n```mermaid\nsequenceDiagram\n    participant 클라이언트A as 클라이언트 A\n 248: ## 7. 핵심 도메인 시스템
249: 
250: ### 7-1. 온톨로지 캔버스 엔진 (M-V-C 아키텍처)
251: 
252: ```mermaid
253: graph LR
254:     subgraph Controller["OntologyCanvasEngine.ts"]
255:         State["상태 (노드, 카메라, 선택)"]
256:         Events["마우스/터치 이벤트 핸들러"]
257:         Tick["tick() → isDirty 플래그"]
258:     end
259: 
260:     subgraph Model["모델 계층"]
261:         Layout["OntologyLayout.ts\n(방사형 좌표, 궤도 수학)"]
262:         Network["OntologyNetwork.ts\n(BFS, 트리 탐색, 가중치)"]
263:     end
264: 
265:     subgraph View["뷰 계층"]
266:         Renderer["OntologyRenderer.ts\n(Canvas 2D 렌더링 파이프라인)"]
267:     end
268: 
269:     Events --> State
270:     State --> Tick
271:     Tick -->|isDirty=true| Renderer
272:     State --> Layout
273:     State --> Network
274:     Layout --> Renderer
275:     Network --> Renderer
276: ```
277: 
278: - **Phase 1 (모듈화):** 약 1,300줄의 단일체 엔진을 컨트롤러 + 레이아웃 + 네트워크 + 렌더러로 완전 분해.
279: - **Phase 2 (Dirty Flag):** `needsRedraw` 플래그로 실제 사용자 상호작용 및 물리 모션 계산 시에만 Canvas 렌더링 수행. 유휴 CPU → 0%.
280: - **Phase 3 (상태 동기화):** `useState`를 `useSyncExternalStore`로 교체하여 Yjs 데이터 구독 개편. 16ms 디바운스로 고빈도 Yjs 트랜잭션을 일괄 처리하여 노드 집중 조작 시 React UI 정지 현상 영구 해소.
281: - **Phase 4 (LOD 텍스트 컬링 및 1차 인접 렌더링):** 줌 비율에 따른 드로잉 분기와 더불어 활성 노드(`activeNodeId`)의 1차 인접 노드(직속 부모/자식)만 라벨 텍스트를 그리고 나머지는 벡터 원(Dot) 형태로 대체하는 LOD 기법 도입.
282: - **Phase 5 (Zero-Allocation 및 정수 인코딩):** 간선 드로잉 배치 맵의 키를 문자열 대신 비트 연산 기반 32비트 정수형(`(colorId << 17) | ...`)으로 변환해 문자열 생성 가비를 억제하고, Object Pool 패턴을 이식해 매 프레임 GC 발생을 원천 차단.

284: ### 7-2. 실시간 협업 스택
285: 
286: ```mermaid
287: sequenceDiagram
288:     participant 클라이언트A as 클라이언트 A
289:     participant 파티킷 as PartyKit 서버

302: - **상태 관리:** `useGraphCustomization` 훅이 Yjs 맵(`overrides`, `customNodesMap`, `customEdgesMap`, `deletedEdgesMap`)을 반응형 외부 스토어로 노출.
